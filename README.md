# 自动重试

SillyTavern 前端拓展。原有报错/空回重试只处理聊天补全生成请求：
`POST /api/backends/chat-completions/generate`。

## 模式

- **不启用**：不干预请求，默认模式。
- **特定报错与空回**：HTTP `429`、HTTP `503`、响应体内的 `429/503` 错误，以及成功响应中的空消息会重试。兼容 SillyTavern 将上游错误包装成 HTTP `200` 和 `Service Unavailable` / `Too Many Requests` 消息的情况。
- **全部情况**：任意 HTTP 错误、响应体错误、网络失败和空消息都会重试。

工具调用、函数调用、图片或音频响应不视为空回。拓展会完整检查流式响应后再交给 SillyTavern，避免重试时重复已经显示的片段，因此开启重试后流式文本会在一轮响应完成后一次性出现。

对于 OpenAI 兼容响应，`choices[].message.content` 为 `""`、仅空格、仅换行或其他纯空白字符串时，均视为空回；`extra_content` 等元数据不会让空消息被误判为有效回复。

## 设置

- **最高重试 RPM**：所有聊天补全请求共享的重试速率上限，默认 `5`。第一次重试可以立即发生，后续重试按此速率排队；服务端 `Retry-After` 会优先采用更长等待时间。
- **最高单次重试次数**：一次原始请求最多增加的尝试次数，默认 `5`。例如设为 `5` 时，最多发送 `1` 次原始请求和 `5` 次重试。

## 安装

在 SillyTavern 的“扩展”面板中点击“安装扩展”，输入以下 Git URL：

```text
https://github.com/xfcgef/ST-auto-retry
```

也可以将整个 `auto-retry` 文件夹放到：

```text
SillyTavern/public/scripts/extensions/third-party/auto-retry
```

重启 SillyTavern，然后在“扩展”设置中展开“自动重试”。

## 手动测试

1. 保持默认“不启用”，确认普通聊天请求只发送一次。
2. 选择“特定报错与空回”，将 RPM 和重试次数暂时设为较小值。
3. 让测试代理依次返回 HTTP `429`、HTTP `503`、`200` 空消息和 `200` 正常消息。
4. 在浏览器开发者工具的 Network 面板中确认生成请求按设置重发，正常消息到达后停止。
5. 改为“全部情况”，用 HTTP `500` 验证它也会重试；切回“特定报错与空回”后，HTTP `500` 应直接交给酒馆。
6. 在流式模式下返回只有 `data: [DONE]` 的 SSE，再返回带内容的 SSE，确认只显示最终的非空回复。

运行核心自动化测试：

```powershell
node --test core.test.mjs
```

## 1.1.0：最后一条 AI 回复的内容重试

在扩展设置选择“特定报错与空回”或“全部情况”，勾选“启用最后一条 AI 回复的内容重试”。默认关闭，已有配置会自动补齐新字段。

- **关键词 / 正则**：每行一条，多个条件任意命中即可。普通关键词使用区分大小写的包含匹配。
- **正则格式**：`/表达式/flags`，例如 `/sorry|cannot comply/i`。可与普通关键词混用。无效正则会在界面提示并跳过，其他有效条件仍生效。以 `/` 开头的行按正则解析。
- **回复长度**：填写非负整数；`0` 关闭长度判断。正文长度严格小于阈值才重试，等于阈值不重试。按 Unicode 码点计数（例如普通 emoji 算 1），包括空格、换行和正文内的 Markdown 标记。
- 关键词、正则、长度之间均为“或”关系。

示例配置：

```text
抱歉，我无法
无法完成请求
/sorry|cannot comply/i
```

长度设置为 `100` 时，命中上述任意规则 **或** 回复少于 100 个码点，就重新生成最后一条回复。

### 聊天记录来源与行为

通过 SillyTavern 扩展 API `SillyTavern.getContext().chat` 读取最新聊天记录，在收到 `MESSAGE_RECEIVED` 并完成 `GENERATION_ENDED` 后检查最后一条 AI 消息的 `mes`。不从页面 DOM 或请求中的历史提示词推断回复，也不提前读取可能尚未保存的服务器聊天文件。跳过用户消息与系统消息，只重试本轮实际收到且仍处于聊天末尾的 AI 回复，检查当前选中的 swipe 正文，不检查思维链元数据。

适用于**单角色聊天**的普通回复、重新生成、swipe 和续写后的完整正文；流式响应在生成完成后检查。命中后调用酒馆 `generate('regenerate')` 替换最后一条回复，因此不合格回复会先显示，再被重新生成。续写命中时会重新生成整条回复。群聊目前跳过内容重试，避免误删或重跑整组成员；原有请求级重试仍保留。

内容重试沿用“最高单次重试次数”，与请求报错重试共享 RPM 限速器。两层的次数预算独立：每次重新生成的 API 请求仍可能在原有机制中重试，因此最坏情况下总请求数可达 `(1 + 最高单次重试次数)²`。达到内容重试上限后保留最后一次回复并提示。

停止生成、切换聊天、手动编辑/删除消息会取消待执行的内容重试。等待期间关闭内容重试或总开关，也不会继续发起重新生成。静默生成、用户代写、欢迎语和没有生成新回复的失败请求不会用旧消息触发内容重试。

### 安装修改版

1. 备份原扩展目录，解压压缩包。
2. 将包内 `auto-retry` 文件夹放入 `SillyTavern/public/scripts/extensions/third-party/`，或将文件覆盖到该项目原来的安装目录；只保留一个副本，避免重复加载。
3. 重启或刷新酒馆，在扩展设置中启用并配置规则。

此压缩包为修改版，版本号 `1.1.0`；已关闭此扩展的自动更新，避免上游自动更新覆盖修改。手动更新前请备份。

### 验证

```sh
node --test core.test.mjs content.test.mjs
```

新增测试覆盖多关键词/正则匹配、非法正则、Unicode 长度边界、聊天记录选择、连续重试上限、取消、旧消息防误触发及等待期间禁用。测试使用模拟酒馆事件，未在真实酒馆服务器连接模型完成端到端测试。

手动验收建议：先用关键词“测试”或较高的长度阈值触发重试；确认最终合格回复停止重试、持续不合格达到上限；分别在流式和非流式模式下测试，再验证等待期间关闭开关与切换聊天。
